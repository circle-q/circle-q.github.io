从0开始学web-01:前端理解

作为一个刚入门的初学者，我深知自己理解抽象概念比较吃力。所以这篇笔记，我决定用“寄快递”的例子来搭建我的 Web 底层框架。参考自 MDN 官方文档以及例会内容。

引子：计算机之间怎么通信？这里比作送包裹。

首先，要把它们连接起来（有线或无线方式）。
阶段一：两台计算机，点对点， 直接给就行。
阶段二：多台计算机，互相通信结构太过复杂，由此出现了网络交换机，相当于中间人，A机把信息给它，它再把信息给B，是个在一栋楼里跑腿的。
阶段三：超多台计算机，一个网络交换机调度不过来，因此把多个交换机连在一起，成树状结构，这样范围就很大了，可以连接一整片小区。 但结构太大会导致传输缓慢，一个环节出错整片崩掉，怎么办？
阶段四：路由器出现了，连接不同小区，靠IP 地址识别包裹。把信息发往各地，连接起各个城市。此为网络运转原理。
而所有网络结合起来，便形成了互联网。

互联网 外联网 内联网

互联网：大马路和公共广场，是全球公开的、谁都能连上的网络，任何人都可以进来逛，访问 GitHub、用浏览器查资料、上 B 站看视频，全都在用互联网。
内联网：公司办公区。是一个组织（比如学校、企业）内部私有的网络，外面的人进不去，里面的人能互相沟通。eg：学校里查成绩的教务系统，只能在校园网里访问。
外联网：VIP客户通道。把内联网稍微开个小口子，允许特定的、经过授权的外部人员（比如合作伙伴、大客户）连接进来。eg:学校有“校外 VPN”。你在家（互联网）通过 VPN 登录学校的 VPN 服务器，就能临时跨越界限，访问学校的内网（教务系统）。

网页 网站 web服务器

网页：单个界面，不能跳转。
网站：由多个网页组成，在网站里可以点击进入不同的网页。
web服务器：互联网是“高速公路网”，而 Web 服务器是建在高速公路旁边的“超级大商场”。顾客（浏览器）顺着高速公路网（互联网），来到商场（Web服务器），买完东西（请求网页），再顺着高速公路网回家（显示网页）。

商场的外观：前端三剑客

那么，顾客（浏览器）是怎么拿到东西的呢？
简单来说，我只要输入一个 URL（网址），就像告诉服务器一个固定地点。服务器找到了对应的文件，就会把它打包发回给我的浏览器。服务器发回来的东西，统统被称为前端三剑客。如果没有它们，网页就是一堆黑白文字。它们是构建整个网页外观和动作的基础。

HTML（骨架）

定义网页的内容与结构。决定了网页哪里是导航栏，哪里是头像，哪里是文章内容。

CSS（皮肤）

控制网页的样式与布局。决定了你的背景是星空还是纯白，文字是黑体还是宋体，头像是不是圆的，以及字体颜色等等。

JavaScript（灵魂）

实现网页的交互行为。决定了我blog首页打字机效果（Keep Learning… 是怎么一个一个蹦出来的）等等。

URL

以前我以为网址就是一串字符，学了以后才明白一个完整的 URL 其实包含了很多部分。
以 http://user:password@tryhackme.com:80/view-room?id=1#task3 为例：

Scheme（协议）：http://
快递的运输方式（明文或加密）。
如果是 http，抓包可以直接看明文；如果是 https，需要配证书解密。
User（用户信息）：user:password@
寄件人的账号密码。
很少见，但遇到 HTTP Basic 认证（如爆破admin密码那题）时就会出现。
Host（域名）：tryhackme.com
收件人的小区地址。
如果后端校验不严，改Host头就是改收件人名字，骗过保安，进去原本不对外开放的内部办公室。
Port（端口）：:80
具体的房间号。默认 HTTP 走 80，HTTPS 走 443。
打moectf做熊出没时，就要改端口去探测内网。SSRF！(服务器代替攻击者发送请求)
Path（路径）：/view-room
你要找的商店的具体位置
容易发生目录遍历或任意文件读取漏洞（如 ../../etc/passwd），跳出文件夹，去偷看服务器深处的机密文件。
Query String（查询参数）：?id=1
给老板提的具体要求。
Web 安全重灾区 SQL 注入，XSS（偷偷写一段JS恶意代码，如果网站没做过滤，这段代码就会被其他用户的浏览器执行，盗取用户的cookie），参数篡改都在这里发生。
Fragment（锚点）：#task3
网页内部的定位（比如直接跳到第三章）。
只在前端生效，不会发给服务器。

HTTP

HTTP = HTTP协议(HyperText Transfer Protocol超文本传输协议）
是国家邮政局颁发的《全国快递寄件规范》。它是一个规则、一套约定。它规定了：“你要寄东西，第一行必须写收件人地址（URL），必须用 GET 或 POST 贴邮票，如果地址写错了必须回一个 404 标签”。输入网址的前缀 http://，以及Burp 里看到的 HTTP/1.1，代表你在遵守这个规矩。
HTTP协议特点：
无状态：没有记忆能力，每次都是要重新来一遍。
无连接：每次连接只处理一个请求。服务器处理完客户的请求，并收到客户的应答后就断开连接。
灵活：HTTP允许传输任意类型的数据对象。

HTTP报文（Message）
就是根据《规范》写出来的、那封实实在在的信件或包裹。报文是具体的数据实体，分为请求报文（你发给服务器的快递）和响应报文（服务器发给你的快递）。

请求报文

第一部分：包裹最外层的单号（请求行）
比如 GET /index.php HTTP/1.1
GET：快递的类别（请求方法）。
/index.php：你要寄到的具体位置。
HTTP/1.1：快递行业的通用规则（协议版本）。

第二部分：箱子里的货物（请求体 Body）
GET 请求：里面一般是空的。因为你是去“拿”信息，比如看文章，你不需要带东西过去。
POST 请求：里面装满了东西。比如你登录时填写的账号密码、上传的文件，全都在这个箱子里。

第三部分：快递单上的附加说明（请求头 Headers）

  1. host：我该把包裹送到哪。即收件人的家庭住址。指明了请求将要发送到的服务器主机名和端口号。在 HTTP/1.1 中，所有请求必须包含 Host 头，否则会报 400 错误。有时候服务器配置不当，黑客通过修改 Host 头指向本地，就能实现“虚拟主机”越权访问。
  2. Referer：你是怎么进来的？你的“介绍信”。告诉服务器你是从哪个门（网页）点过来的。包含了当前请求页面的来源页面的地址。有些后台限制“只能从内部管理页面点击进入”，用 Burp 抓包，伪造一个 Referer: \http://admin.com，就能骗过服务器拿到管理员权限。
  3. Origin：你从哪里来？（跨域版）
    · 大白话：和 Referer 类似，也是个查户口的，但它只查户籍地，不查具体门牌号。
  4. Cookie：你的身份门禁卡。一张记录了你登录状态的卡。服务器靠它认出你是“老客户”。
    eg:把 Cookie: admin=0 改成 admin=1，越权访问。
    但这张卡如果被黑客偷了，号就没了。所以服务器给 Cookie 加了三个封印：
    Domain（划地盘）：规定这张卡只能在哪个网站用。
    HttpOnly（防盗保险柜）：我不想让别人用我的卡。加了它,JavaScript 脚本就偷不到Cookie。
    SameSite（防跨站伪造）：防止黑客用钓鱼网页，骗你的浏览器自动带上 Cookie 去给陌生人转账。 eg:你刚登录了银行网站（拿到了 Cookie），然后你手贱点开了一个黑客发你的搞笑网站。黑客的网站后台偷偷写了一行代码：“向银行发送转账 10000 元请求”。如果没加 SameSite，浏览器会傻乎乎带着银行的 Cookie 去发这个请求，钱就没了。如果服务器设置了 SameSite=Lax 或 Strict，浏览器在跨站发送请求时，就绝对不会带上这个 Cookie。银行一看你没带门禁卡，直接拒绝转账。
  5. X-Forwarded-For (XFF)：你的真实家庭住址。用来记录你真实的 IP 地址。因为经过了代理服务器（代购)，服务器只能看到代理的 IP，XFF 就是用来记录最初是谁买的。

这里是搜索得到的常见套路：
套路一：伪造本地 IP（绕过白名单限制）。有些题目的后台会限制：“只允许管理员在本地服务器上访问。”你用 Burp 抓包，直接往请求头里加一行：X-Forwarded-For: 127.0.0.1。服务器一看是本地管理员来了，直接把 Flag 交出来。
套路二：绕过防爆破限制。有些登录页面会限制：“同一个 IP 连续输错密码 5 次，就封禁这个 IP。”你用 Burp 里的攻击器 (Intruder) 爆破密码，每次请求都带上不同的 XFF（比如 X-Forwarded-For: 1.1.1.1, 1.1.1.2…），服务器就会以为有千千万万个不同的电脑在试密码，就不会封你了。
套路三：SQL 注入 / XSS。如果后端程序员很粗心，把你的 XFF IP 直接写进了数据库里，或者直接打印在页面上，你就可以在这个头里直接塞入数据造成漏洞。

响应报文

服务器处理完你的快递后，会回寄一个“响应报文”收件人的签收回执（响应报文）。包裹的最外层写着状态行。

状态码 描述
200 - 确定 请求已成功完成。
201 - 创建 已创建资源（例如新用户或新博客文章）。
301 - 永久重定向 这会将客户端的浏览器重定向到一个新网页或告诉搜索引擎该页面已移动到其他地方…
302 - 临时重定向 类似于上面的永久重定向，但顾名思义，这只是暂时的改变，不久的将来可能会再次改变。
400 - 错误请求 这告诉浏览器他们的请求中有错误或缺失。如果正在请求的 Web 服务器资源需要客户端未发送的特定参数，则有时可以使用此状态码。
401 - 未授权 目前不允许您查看此资源，直到您通过网络应用程序获得授权，最常见的是使用用户名和密码。
403 - 禁止 无论您是否登录，您都无权查看此资源。
405 - 方法不允许 资源不允许此方法请求，例如，当它期望 POST 请求时，您向资源 /create-account 发送了 GET 请求。
404 - 页面不存在 您请求的页面/资源不存在。
500 - 内部服务错误 服务器在您的请求中遇到了某种错误，它不知道如何正确处理。
503 - 服务不可用 此服务器无法处理您的请求，因为它超载或停机维护。

快递柜上的特殊标签：Allow（响应头）
服务器告诉你，这家店允许你用哪种姿势进门。如果服务器返回了 405 Method Not Allowed 状态码，它必定会同时返回一个 Allow 头（比如 Allow: GET, POST, HEAD）。遇到报错看一眼 Allow 头，就知道该换什么方法再去请求了。

再过一遍
假设你（浏览器）要去淘宝（服务器）买东西：

  1. 你们双方必须先达成一个共识：必须遵循 HTTP 协议（规则）。
  2. 于是，你写了一封信，信头写着“我要用 GET 方法”，信的内容是“我要买鞋子”。这封信，就是HTTP 请求报文。
  3. 淘宝收到信，发现“哎呀，没货了”，于是回了一封信，信头写着“状态码 404”，信的内容是“对不起”。这封信，就是HTTP 响应报文。
