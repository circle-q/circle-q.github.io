一些我不清楚但解决了的概念

  1. 动态表名
    正常写死的表名：SELECT * FROM users WHERE id = 1; （表名 users 是固定的）。

动态表名：
假设你开发了一个多租户的电商系统，系统里有一张表叫 orders_2023，还有一张表叫 orders_2024。
用户在前端点击“查看2023年订单”，前端传来参数 year=2023。
后端代码如果是这样写的：
String tableName = “orders_” + year;
String sql = “SELECT * FROM “ + tableName;
这里的 tableName 就是动态表名。同理，后台管理系统允许管理员在页面上切换想看哪个表的数据，这也需要用到动态表名。

为什么危险？
如果攻击者把参数改成 year=2023; DROP TABLE users; –，拼出来的语句就变成了：
SELECT * FROM orders_2023; DROP TABLE users; –
直接把你的用户表删了！而且，预编译的 ? 是绝对不能放在表名位置的（写成 SELECT * FROM ? 会直接报 SQL 语法错误），所以预编译在这里防不住。

  1. 白名单映射

既然预编译防不住动态表名，过滤（黑名单）又容易被绕过（比如把 select 换成 sel<>ect），怎么办？使用白名单映射（也称为字典映射）。

白名单映射的意思就是：代码里预先规定好“允许拼进去的名字”，用户传的只是“代号”，代码通过代号去查你规定好的名字。

错误做法（直接拼接）：

正确做法（白名单映射）：

无论用户输入什么花里胡哨的 payload，只要不在这个 Map 的键里，就取不到值；只要取到了值，拼进 SQL 的永远是程序员自己写死的绝对安全的字符串（如 “users”），用户输入根本没有进入 SQL 语句。

  1. 为什么要转化成 order by

为什么不能直接拼接 ORDER BY？
假设前端有个点击表头排序的功能，URL 是 ?sort=age。
后端如果直接拼：SELECT * FROM users ORDER BY $sort。

· 攻击者传 ?sort=(select sleep(5))，就变成了时间盲注；
· 传 ?sort=extractvalue(1,concat(0x7e,database()))，就变成了报错注入。

为什么不用预编译？
如果写成 ORDER BY ?，数据库会把它当成一个普通的字符串常量（比如查出来就是按字母 “?” 排序），而不是按某个字段排序。数据库要求 ORDER BY 后面必须明确是“列名”或“列的位置（如1,2,3）”。

正确的转化（映射）方式：
和动态表名一样，排序字段也必须用白名单映射！

如果有升序降序（ASC/DESC），也要用同样的方式判断：如果前端传 order=desc，就拼接 DESC，否则默认 ASC。

因为表名和排序字段属于 SQL 的“结构（Syntax）”，而预编译的 ? 只能替代“数据（Data）”。处理结构问题，必须用白名单映射。只要保证拼进 SQL 语句的字符串绝对是由后端控制的白名单内容，SQL 注入就无从谈起。
