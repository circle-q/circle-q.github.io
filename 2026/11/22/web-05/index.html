git

是项目开发中常见的分布式版本控制系统，总之呢就是一个存档读档的好工具。你把你的代码笔记提交上去，它就会记录你写了哪些内容，删了哪些内容。
使用方法
新建文件夹，自己命名一下，然后右键git bash here (感觉和写博客一样)
首先git init，来建立git仓库。
然后把写的东西放到文件夹里
敲 git add . 别忘记这个.了！这个是把写的东西放进去让它知道的
敲 git commit -m “取一个标题” ，它就存档了
git log查看我的存档，如果我删了那这个文件就没有了，不会显示在这里面
git refolg真正的查看历史记录，你的存档读档包括删除都可以看到
git restore 文件名 （不是我取的标题）
这是在我还没有建立新存档时，我想直接回到上一个存档点用的
git reset –hard 一堆乱码（这个是在git log 里面记录的，commit后面那一串）选取想回到的那个存档所在的乱码就行

RCE

远程代码执行 (Remote Code Execution)：攻击者的输入被当作代码（如PHP、Python脚本）的一部分来执行。
远程命令执行 (Remote Command Execution)：攻击者能够通过应用程序，在服务器上执行操作系统命令（如 whoami、ping）。

产生RCE漏洞的根本原因，通常是应用程序对用户输入没有进行充分的过滤或验证，就直接将其传入了危险的执行函数中。一旦被利用，攻击者可以窃取敏感数据、植入后门，甚至将受控机器作为跳板攻击内网。想起了SQL注入！

RCE 和 SQL 注入确实都是是不可信的用户输入，没有被正确限制在“数据”的边界内，结果被解释成了“代码/命令/查询语法”。

但是RCE其实不算漏洞，它是漏洞导致的危害性的结果。

序列化和反序列化

序列化：把内存里的对象（比如有名字、年龄的用户），变成一串字符串来存储。相当于把高达拆成零件运输，顺便给人送了个说明书
反序列化：把这串字符串，重新变回对象。程序拿到数据后，得还原成对象才能继续用。就是照着说明书拼出乐高。

这个说明书呢就是一个格式化描述

O:4:”User”:2:{s:4:”name”;s:5:”admin”;s:3:”age”;i:18;}

那为什么所有语言都要序列化？

比如Python 程序里有一个爬虫对象，里面装了requests.Session、Cookie这一堆。想把它存下来明天接着用的话也不能直接把这堆内存写入文件，因为它依赖当前运行的进程（意思差不多是说正在发生的这个时间点的现场，活在当下）
所以，任何语言想“持久化”或者“跨进程通信”，都必须把对象变成字节/字符串。这个过程就叫序列化。

JSON：最通用的序列化格式（跨语言）。
PHP serialize：PHP 专用，长得像天书。
Python pickle：Python 专用，二进制。
protobuf：Google 的高效二进制序列化格式。

session和cookie的区别

看起来都比较像身份牌，之前没有做什么区分，简单区分一波
session数据存在服务器上，在第一次登录时服务器创建一个session然后把它塞到cookie里面发给浏览器
cookie数据存在自己电脑上，是服务器发给浏览器的一小段文本，每次请求时自动带上

session比cookie安全多了，因为它的话用户看不到，不能随便改，但是cookie就可以
