小小问题

判断字符型还是数字型注入

and 1=1与and 1=2

都能正常回显，则为字符型注入(它现在只把1=2当成字符来对待，不进行计算判断)

第二个报错了，则为数字型注入，它要看1是不是=2，显然不对，所以就报错了

小拓展

可以用?id=2-1（也就是做运算），如果是数字型，那就是输出id=1时的结果了，如果是字符型，它不管运算，如果是字符型就不会变。

但是目前做题字符型都是只看最前面的数字，因为它是搞了弱类型转换
id原来是整数型，但是我输入了2-1变成字符型，mysql会强行把字符串转化成数字，从左往右读，遇到非数字就停下，所以只读了前面的数字。

为什么不用加号？

因为+是会被理解成空格的,那这个算数式子不是白造了吗

为什么前面要写问号

URL 传参（GET 请求）。
? 是网址（URL）里的一个特殊符号，用来告诉服务器：“我要给你传参数了”。
它是分隔符。? 前面的部分（http://…/Less-1/）是你要访问的页面路径，? 后面的部分（id=1）是你要传给这个页面的数据（叫做 Query String）。

/是干嘛的

加 / 代表这是一个“文件夹（目录）”：比如 http://…/Less-1/，意思是访问 Less-1 这个文件夹。

不加 / 代表这是一个“文件”：比如 http://…/index.php，意思是直接访问这个具体文件。

一般它都会自己再识别一下，如果是一个文件夹但是你没加/,会自动给你补一个，把你写的那个网址给跳转到正确的地方，这个就是重定向

重定向

重定向出现在什么情况

  1. 结尾加不加斜杠：
    当你访问 http://…/Less-1（不加斜杠），服务器发现这是个文件夹，就会返回一个 301 重定向，把你踢到 http://…/Less-1/（加斜杠）
  2. 登录成功后的跳转：
    你在登录框输入账号密码，提交后，服务器验证通过，会返回一个 302 重定向，把你带到“个人中心”页面
  3. 安全防御（WAF拦截）：
    如果你在测试 SQL 注入，输入的 Payload 太嚣张（比如带了 union select），被WAF拦截了。安全狗经常会给你返回一个 302 重定向，把你强制踢回首页，或者踢到一个“您的请求不合法”的页面。这时候你看不到报错，因为被重定向走了

区分重定向与无回显

这个重定向它会不显示内容，那跟无回显到底一样不一样呢

不一样

真正的无回显（盲注）：是代码写了 select * from users where id = 1’，然后数据查出来了，但是代码里没写 echo 输出，所以页面上干干净净。数据库实打实地执行了你的语句。

重定向拦截：是代码（或者WAF）发现你带了 ‘ 或者 select，直接给你掐断了（或者跳转走），数据库可能压根就没执行你的语句。

怎么直接看

  1. 抓包拦截：用 Burp Suite (抓包工具) 拦截请求。因为 Burp 默认不会自动跟随跳转，你能直接看到服务器返回的 302 响应头。如果里面有报错信息，你能直接看到。
  2. 浏览器停止加载：如果你用浏览器，一敲回车，迅速按下键盘上的 Esc 键（停止加载），这样浏览器就不会跳转，你就能看到原本的报错页面了。
  3. 看 Network (网络) 面板：按 F12，打开 Network，勾选 Preserve log（保留日志）。看看那个 302 请求的 Response 里到底写了啥，再对比跳转后的新地址有没有线

Payload

字面意思是“有效载荷”，在渗透测试语境下指我构造出来的、用来攻击或测试的那段攻击指令

输入的特征太明显，会被WAF（web应用防火墙）发现，给你拉入黑名单
比如说：

  1. 高频词汇：直接出现 UNION、SELECT、SLEEP、INFORMATION_SCHEMA、UPDATEXML。
  2. 敏感符号：直接出现单引号 ‘、双引号 “、注释符 – 、井号 #。
  3. 特殊函数：直接出现 DATABASE()、USER()。

怎么在测试时发现我被拦截了？

状态码突变：正常访问是 200 OK，你带上 Payload 后，F12 里显示状态码变成了 403 或者404

弹窗警告：页面没报错，而是直接跳转到一个“您的请求含有非法字符”、“您的IP已被封禁”的页面

页面空白：刚才还好好的，一加 union select 页面直接白了，连正常的排版都没了

强制重定向：就我刚才说的，一加敏感词，直接被 302 重定向踢回了首页

回显位

什么叫回显位

这段代码只准备了3个坑来展示数据库查出来的结果。

坑 1用来放账号的 ID
坑 2用来放用户名（Your Login name）
坑 3用来放密码（Your Password）

输入 ?id=-1’ union select 1,2,3 –+ 时，你实际上是让数据库不管里面的数据了，强行把数字1,2,3放到这 3 个坑里，数据库就把1塞进坑1 2塞进坑2 3塞进坑3。然后网页把这展示出来，网页上能把你塞进去的东西显示出来的那个位置，就是回显位。

为什么要找它

让网页把我们想要的数据打印出来。知道了2个坑和第3个坑可以显示字后，把数字2换成数据库的查询语句，网页就变成显示器了

函数及括号

database()

它是一个 MySQL 数据库自带的系统函数，当你把 database() 发给 MySQL 时，就是问它数据库名称是什么，MySQL 会执行这个函数，然后告诉你一个结果。

group_concat

用来把多行数据拼接成一行

为什么用它？
假设 security 库里有 4 张表，当你查表名时，数据库其实查出了 4 行数据（emails、referers、uagents、users）。
但网页上的回显位只够显示第一行，后面的全被吞了。
这时，你把 table_name 放进括号里：group_concat(table_name)。MySQL 的这台打包机就会把查出来的 4 个表名，用逗号连在一起，变成一个长字符串：emails,referers,uagents,users。这样网页才能一口气把它们全显示出来。

后面的括号里加不加东西

group_concat

group_concat是让它把括号里的东西拼一起的，得告诉它拼啥它才能工作。group_concat(table_name)。
如果你写成空的 group_concat()，它会直接报错，因为它不知道要拼什么东西。

database

数据库本身就知道当前自己正在哪个库里工作，你只要查询一下它就会直接把你想要的结果返回给你。

所以database 后面的那对空括号 ()是让它自己去查了告诉你的

其他空括号函数

version()：查数据库版本

user()：查当前连接数据库的账号

now()：查当前时间

concat

是 MySQL 里的一个内置函数，全称concatenate，意思就是拼接它的作用就是把括号里的多个东西，头尾相连地粘成一个长字符串。·

区分它与group_concat

concat() 是拼同一行里面不同列的
比如表里有一行数据：username 是 admin，password 是 123。
你写 concat(username, 0x3a, password)，它把同一行的账号和密码粘起来，变成：admin:123。

group_concat()拼同一列里面不同行的S
表里有 3 个用户：admin、dumb、angelina。
你写 group_concat(username)，它把这 3 行不同的用户名，打包成一行，中间用逗号隔开，变成：admin,dumb,angelina。

单引号

C 语言里的单引号和 SQL 里的单引号，用法和含义完全不同。
在 SQL 里，单引号是用来包字符串（文字）的
但在 C 语言里，单引号是用来包单个字符的

加与不加

只要你要找的是“叫这个名字的东西（数据）” 加单引号（比如 where table_name=’users’ 或者 id=’1’）。
只要你是要“去这个地方/拿出这个东西（表名/列名）” 不加单引号（比如 from users 或 select password）

重要的表名

如果表名叫 admin、users、manager，里面大概率有高权限账号
如果表名叫 config、settings，里面可能有数据库连接密码、后台密钥
如果表名叫 orders，里面是订单信息（有时候会有身份证、手机号等敏感信息）

schema

在很多数据库里，schema 就是“模式”，可以当成Database的同义词。在 MySQL 里，schema 和 database 是一回事。所以 table_schema 的意思就是“这个表属于哪个数据库”。

0x3a

就是冒号
如果不加任何分隔符，group_concat把用户名和密码打包在一起，比如adminadmin，就不知道哪点是账户哪点是密码了，所以我们需要在中间加个符号隔开。

注意

不能直接写成冒号group_concat(username, ‘:’, password)

我们现在的注入环境，外层原本就有一个单引号 id=’$id’。如果我们的 Payload 里面再出现单引号，就极容易发生引号冲突，导致闭合失败，直接报错。

用 0x3a 好处
它是一个十六进制数字，不需要加任何单引号，放在 SQL 语句里绝对安全，不会破坏原本的闭合结构，而且防火墙通常不会去拦截一串数字。

and和or

测试的时候首选and，而利用或者绕过的时候经常用or

区别

假设原代码是 SELECT * FROM users WHERE id=1。
这句话的意思是：“给我找 id 等于 1 的用户”。

and：必须两边都满足，结果才成立。
id=1 AND 1=1：找 id=1 的用户，并且 1 等于 1（真话）。结果：成立，正常显示用户。
id=1 AND 1=2：找 id=1 的用户，并且 1 等于 2（假话）。结果：不成立，查不到东西。
or：只要有一边满足，结果就成立。
id=1 OR 1=1：找 id=1 的用户，或者 1 等于 1。结果：成立。
id=1 OR 1=2：找 id=1 的用户，或者 1 等于 2。因为 id=1 已经满足了，所以结果：依然成立

使用and

因为你的目的是制造真与假的对比，看看页面有没有反应，从而判断是不是存在注入。

如果在测试时输入 ?id=1 OR 1=2 –+， id=1 这个条件本身就是真的，OR 后面的假话根本不影响大局，页面依然正常显示。得不到任何报错或空白，就没法判断到底存不存在注入。

但如果用 ?id=1 AND 1=2 –+，因为 1 永远不可能等于 2，整个条件崩溃，页面查不到东西（或者报错）。这种页面异常可以知道我注入的有效了

使用or

万能密码

很多登录框的代码是：SELECT * FROM users WHERE username=’$user’ AND password=’$pass’。
如果在账号框输入 admin’ OR 1=1 –+，密码随便填。
拼出来变成：SELECT * FROM users WHERE username=’admin’ OR 1=1 –+ ‘ AND password=’…’
因为 1=1 永远成立，所以不管密码对不对，都会直接登录成功

强行爆全表数据

在注入时，如果你输入 ?id=1 AND 1=1，网页通常只显示 id=1 那一个人的数据。
但如果你输入 ?id=1 OR 1=1，因为 1=1 对表里所有人都成立，网页就会把表里所有的用户都吐出来。
